# PELLET MARKET INTELLIGENCE

## Финальное техническое задание для Codex

**Тип проекта:** веб-приложение для мониторинга и анализа рынка древесных пеллет.

**Стек:** Astro, TypeScript, Tailwind CSS, React Islands, GitHub Pages, GitHub Actions.

**Языки:** русский (основной), немецкий, английский.

**Регион:** Германия с возможностью расширения на Европу и Канаду.

**Основные локации:** Berlin, Brandenburg, Brake, Bremerhaven, Bremen, Hamburg.

**Репозиторий:** `pellet-market-intelligence`

---

# 1. Главная задача

Создать полноценную аналитическую платформу для изучения рынка древесных пеллет, которая позволит:

1. Мониторить цены на древесные пеллеты в Германии.
2. Видеть фотографии пеллет и их упаковок.
3. Определять производителей, бренды и продавцов.
4. Сравнивать стоимость мешков, палет, оптовых партий и навальных пеллет.
5. Пересчитывать любую цену на одну тонну.
6. Рассчитывать стоимость доставки до Берлина.
7. Анализировать историю изменения цен.
8. Исследовать торговую цепочку от производителя до конечного покупателя.
9. Оценивать потенциальную прибыль от закупки и перепродажи.
10. Сравнивать перепродажу готовых пеллет, собственную фасовку и собственное производство.
11. Моделировать экономику строительства пеллетного завода в районе Brake/Bremerhaven.
12. Оценивать влияние закупки древесины, щепы и опилок на себестоимость готовой продукции.

**Важно:** это должен быть работающий аналитический инструмент, а не просто информационный сайт или визуальный макет.

# 2. Общая архитектура

Использовать:

- Astro с `output: "static"`.
- TypeScript со строгой типизацией.
- Tailwind CSS.
- React только для интерактивных элементов.
- Apache ECharts для графиков.
- Zod для валидации данных.
- Vitest для тестирования.
- JSON для хранения предложений, производителей, индексов и истории цен.
- GitHub Actions для автоматического сбора и обновления информации.
- GitHub Pages для публикации.

Допускается использование дополнительных библиотек, если они облегчают реализацию, но не усложняют обслуживание.

Не использовать в первой версии обязательные платные API, серверную базу данных или постоянно работающий backend.

Сбор данных выполнять в GitHub Actions, а не в браузерах посетителей сайта.

GitHub Pages должен получать уже подготовленные и валидированные данные.

Пользовательские настройки и сценарии калькуляторов хранить локально в браузере с возможностью экспорта и импорта JSON.

# 7. Сравнение упаковок и стоимости одной тонны

Любая цена должна переводиться в €/т.

Формула:

`pricePerTon = productPrice / weightKg * 1000`

Примеры:

| Фасовка           | Эквивалент одной тонны |
| ----------------- | ---------------------: |
| Мешок 10 кг       |             100 мешков |
| Мешок 15 кг       |            66,67 мешка |
| Мешок 20 кг       |              50 мешков |
| Палета 65 × 15 кг |                 975 кг |
| Палета 66 × 15 кг |                 990 кг |

Отображать отдельно:

- Стоимость физической упаковки.
- Эквивалент €/т.
- Стоимость покупки целого количества мешков.
- Фактически приобретаемую массу.

Не путать нормализованную цену одной тонны с необходимыми расходами на покупку целого количества упаковок.

Денежные расчёты должны быть точными, с предсказуемыми правилами округления.

## Принцип достоверности

Реальная закупочная цена конкретного магазина обычно неизвестна.

Поэтому необходимо разделить:

- Подтверждённые публичные цены.
- Реальные полученные коммерческие предложения.
- Пользовательские предположения.
- Расчётные цены модели.

**Не утверждать, что разница между ценой производителя и магазинной ценой является фактической прибылью магазина.**

Разница может включать перевозку, склад, упаковку, маркетинг, потери, НДС и другие расходы.

## Интерактивный сценарий

Пользователь меняет закупочную цену, перевозку, фасовку и наценку.

Вся цепочка немедленно пересчитывается.

Отображать waterfall chart, показывающий, как формируется конечная цена.

Добавить сравнение разных каналов сбыта и сценариев.

# 12. Собственный пеллетный завод

Создать отдельный раздел `/factory`.

Это один из ключевых модулей проекта.

Основная цель — оценить экономику строительства собственного производства в районе Brake/Bremerhaven.

По умолчанию создать сценарий:

**Пеллетный завод производительностью 6 тонн готовой продукции в час.**

Это первоначальный расчётный сценарий, а не подтверждённая характеристика выбранного оборудования.

Пользователь должен иметь возможность изменить все параметры.

- Смен в сутки.

## 12.2. Сырьё

- Круглую древесину.
- Древесную щепу.
- Опилки.
- Стружку.
- Смеси этих видов сырья.

Для каждого сырья указывать:

- Влажность.
- Содержание сухого вещества.

- Долю непригодных примесей.
- Потери при подготовке.

- Необходимость измельчения.

Не допускать простого перевода кубометров древесины в тонны без учёта плотности и влажности.

## 12.3. Материальный баланс

Сделать полноценную модель материального баланса по сухому веществу.

Влажность задавать по влажной массе (wet basis).

Расчёт должен учитывать:

- Исходную влажность сырья.
- Требуемую конечную влажность.
- Потери сухого вещества.
- Отходы при подготовке.
- Выход готовой продукции.

Формула базового расчёта без потерь:

`dryMass = wetInputMass * (1 - initialMoisture)`

`finalMass = dryMass / (1 - finalMoisture)`

Потери сухого вещества учитывать отдельно.

Рассчитывать количество воды, которую необходимо удалить при сушке.

Например, влажные опилки и сухие опилки не могут иметь одинаковый расход массы на тонну готовых пеллет.

Рассчитывать:

- кВт·ч/час.
- кВт·ч/год.

- Годовые затраты.

## 12.5. Сушка и собственная теплоэнергия

1. Покупная тепловая энергия.
2. Котёл на щепе.
3. Котёл на древесных отходах.
4. Использование собственных пеллет.
5. Комбинированная система.
6. ТЭЦ/когенерация как дополнительный сценарий.

Параметры:

- Потребность в полезном тепле на тонну удаляемой воды.
- Теплотворность топлива.
- Влажность топлива.
